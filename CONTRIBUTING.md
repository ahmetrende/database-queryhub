# Contributing

Thanks for considering a contribution. The bot is small and opinionated;
contributions should be too.

## Ways to help

- **Bug reports** — open an issue with the smallest reproducer you can.
- **Feature requests** — open an issue describing the use case before
  writing code; we may already have a planned approach in
  `docs/OPERATIONS.md` or the migration history.
- **Pull requests** — see below.

## Pull requests

- One PR per change. Small, focused diffs review faster.
- Bash / Python / SQL: follow the style of files you're touching.
  Python is PEP-8-ish; comments explain *why*, code explains *what*.
- Update `docs/OPERATIONS.md` and `docs/SCHEMA.md` if your change
  affects bot behavior or DB schema.
- Migrations are append-only, numbered sequentially (`migrations/NNN_*.sql`),
  idempotent (`CREATE ... IF NOT EXISTS`, `INSERT ... ON CONFLICT DO NOTHING`,
  etc.). Never edit a committed migration — add a new one.
- Commit messages: imperative subject ("fix CSV streaming truncation"),
  body explains the *why* and any user-visible impact.

## Local dev

One command, and it is the same stack CI runs:

```bash
docker compose up            # app + metadata DB + a seeded demo target
```

Sign in at http://localhost:8080 as `demo-admin` / `queryhub-demo`. The demo
target holds ~10k generated rows and the three per-tier roles, so you can
exercise the whole submit → approve → execute → masked-result path without
provisioning anything. `scripts/ci_demo_roundtrip.py` drives that path
end-to-end and is the fastest way to check a change did not break it.

For the Python side without containers:

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev,slack]"
pytest                       # ~7s, no database needed
ruff check src tests scripts
```

The suite is hermetic by construction: a unit test that reaches for a real
database connection fails with a named error rather than hanging. If you need a
real one, mark the test `@pytest.mark.integration` and run with
`QH_RUN_INTEGRATION=1`.

Frontend:

```bash
cd QueryHubWeb/app && npm ci && npm run build
```

`src/index.css` is generated from `QueryHub.html`'s `<style>` plus
`src/index.local.css` — edit those, not the generated file. `deploy/INSTALL.md`
covers a real install; you do not need one to contribute.

## Good first contributions

Real, self-contained, and each one lands as a small PR. Not a wish list — these
are things the project actually wants:

1. **A `pii_region` pack for one more country.** `pii.py` has a generic pack
   (IBAN, card, email, E.164) and one region. Adding another is a detector plus
   tests, with the checksum algorithm as the interesting part.
2. **A MySQL/MariaDB engine spec.** `engines.py` documents the contract;
   `mssql_exec.py` is the worked example of a non-Postgres engine. The safety
   spec (dialect, keyword classification, dangerous functions) can land before
   the driver path and is useful on its own.
3. **More tautology corpus entries.** `tests/corpus/tautologies.txt` is designed
   to be appended to. Find a WHERE clause that cannot filter rows and is not
   caught yet — that is a genuinely valuable PR.
4. **Timezone hardcoding.** A single timezone appears as a default in several code
   paths and in operator SQL snippets in `docs/OPERATIONS.md`. Make them read the
   configured display timezone.
5. **Grid keyboard paths.** The result grid now supports arrow-key navigation;
   column resize and sort are still mouse-only.
6. **`docs/SCHEMA.md` drift.** It is regenerated by hand. A script that emits it
   from the live schema, so it cannot go stale again, would be welcome.

Deliberately **not** on this list: splitting `slack_app/handlers.py`. It is a
large file and it will get restructured, but it is the worst possible first
contribution.

## Security

If you find a security issue, please email the maintainer directly
instead of opening a public issue. Sensitive concerns include:

- SQL injection / sandbox escape in `query_safety.py`
- Authz bypass (admin / bypass / team grants)
- Secret handling in `crypto.py` or `secrets_store.py`
